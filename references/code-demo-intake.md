# 从 Demo 代码还原产品

仅在 `product.source.mode: demo` 时读取本流程。目标是用代码证据恢复产品事实，找用户确认产品意图，再进入常规交互 PRD 作业；不是代码质量评审，也不默认修复 Demo。

## 1. 建立安全的代码地图

先用只读方式记录代码快照（优先 Git commit）、技术栈和目录结构。用 `rg --files` 等文件索引定位关键代码，排除：

- `.git/`、`node_modules/`、vendor、dist/build、coverage、缓存和生成目录；
- minified/bundle、二进制、大型数据文件；
- `.env*`、凭据、证书、私钥、token、真实用户数据和日志中的敏感信息。

优先阅读清单：包/项目清单、入口文件、路由、页面/视图、共享状态、领域模型/schema、API handler/service、权限与验证、fixtures/mock、测试、样式 tokens、主题和共享组件。根据实际技术栈调整，不要求穷举所有源文件。

静态阅读通常足够。只有无法确认运行时行为时才提出运行 Demo；在安装依赖、执行未知脚本、迁移数据库或连接外部服务前，向用户说明具体命令、写入和网络影响并等待许可。

## 2. 抽取功能、规则与边界

维护 `shaping/00-code-evidence.md`，至少覆盖：

1. 模块、页面、路由、入口和出口；
2. 用户可执行动作、主路径和跨页跳转；
3. 角色、权限、可见性和操作限制；
4. 数据对象、字段、状态机、校验、计算和默认值；
5. API、外部依赖、异步任务、错误处理和恢复路径；
6. 空、加载、失败、离线、超时、禁用和边界状态；
7. 测试或示例数据表达的隐含业务规则；
8. 未实现入口、占位逻辑、硬编码值和疑似技术妥协。

每条重要结论给出最小充分的 `path:line` 证据，并使用以下分类：

| 分类 | 含义 | 后续处理 |
| --- | --- | --- |
| 已实现事实 | 代码明确执行的可观察行为 | 回写 shaping，仍允许用户否定 |
| 有证据推断 | 多处实现共同指向，但未显式声明 | 向用户确认后采用 |
| 待确认 | 代码无法回答产品动机或目标 | 进入问题清单 |
| 疑似技术偶然或缺陷 | 可能是占位、Bug、技术限制或不一致 | 不固化为 PRD 规则，单独请用户裁决 |

不要把组件名、函数名直接改写成用户需求；先恢复用户任务、触发、规则和结果。不要把缺失功能解释为“明确不做”，也不要把 mock 数据解释为真实业务范围。

## 3. 回写 shaping 并确认意图

把代码证据分别回写：

- 产品定位、角色和场景 → `01-product-shaping.md`
- JTBD 候选及代码无法回答的动机 → `02-jtbd.md`
- 已实现范围、明显缺口、疑似占位 → `03-scope.md`
- 页面、流程、跳转和关键状态 → `04-pages-and-flows.md`
- 推断、冲突和意图差异 → `05-open-questions.md`

向用户提交一次“代码还原审核包”：

- 已实现的模块与主流程；
- 关键业务规则、权限、数据和边界；
- 代码实现与可能产品意图不一致之处；
- 无法由代码回答的用户、目标、价值和指标问题；
- 建议保留、修改或删除的实现行为。

用户确认后，把确认版本追加到 `06-shaped-brief.md`。确认前不得起草正式 PRD 或把 Demo 直接包装成交互原型。

## 4. 还原或接入 DESIGN.md

先查找用户提供的独立设计规范、设计 tokens 或明确的品牌文件。存在时以它为权威来源，跳过代码样式反向提取；在 `reference/DESIGN.md` 登记来源、适用范围，并列出 Demo 与规范的差异，不擅自改写用户规范。

未提供独立规范时，优先阅读：

- CSS variables、theme/tokens 配置、全局样式和 reset；
- 字体加载、字号/字重/行高；
- 颜色、间距、栅格、圆角、边框和阴影；
- 布局壳、断点、固定视口与移动/桌面策略；
- 共享组件的变体、状态、反馈和动效；
- 图标、图片、插画等资源及许可线索；
- 可访问性相关的 focus、contrast、keyboard 和触控目标。

将高频重复值整理为候选 token，但不能因为某个值出现一次就把它提升为设计规范。`DESIGN.md` 中明确区分：

- **已观察**：代码中稳定、重复、可引用证据的设计事实；
- **候选规范**：从重复模式归纳，等待用户确认；
- **建议修订**：为一致性或可访问性提出，不属于当前 Demo 事实；
- **不一致/设计债务**：同义多值、一次性样式、组件分叉或平台冲突。

若需要浏览器计算样式或截图才能确认，只在 Demo 已可安全运行并获得必要许可后进行。最终先让用户确认 `DESIGN.md`，再以它生成组件/状态参考和后续交互原型。
